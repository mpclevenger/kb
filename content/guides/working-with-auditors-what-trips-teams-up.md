title: Working with auditors: what trips teams up
section: audit_prep

Auditors test what you can show, not what you meant to do. These are the habits that help avoid problems.

## Evidence

- **Screenshots show their context.** Capture the full window with the timestamp and the system name or URL visible, not a cropped or undated image.
- **Evidence is recorded when things happen.** A review signed off weeks later or a ticket raised after the fact is usually reported as a test exception. Dates are never changed: backdated evidence is a serious integrity problem.
- **Exports are sent as produced.** If you filter one, keep the original and document the filter, rather than deleting rows, hiding columns or re-sorting without saying so.
- **Evidence matches the request.** Check the dates and items asked for before you send.
- **Evidence is kept in the shared evidence location**, not a personal drive or inbox, for the period in the firm's [records retention schedule](#todo-records-retention-schedule).

## Populations and reports

- **User lists and change lists can be reproduced.** Save the query or report settings, the run date and the record count.
- **Completeness is shown, not assumed.** Show how you know a report is complete and accurate, using the source count and the query logic. See [Can you trust the report?](/guides/can-you-trust-the-report/).
- **Exclusions are recorded up front.** Document every exclusion, such as service accounts, and the reason before the control runs.
- **Evidence is kept for every run in the period**, not only the latest, because samples are drawn from the whole period.

## Running the control

- **There is a named backup performer**, so leave or a team change doesn't cause a gap. A missed run is a test exception even if nothing went wrong that period.
- **Reviews record what was looked at**: what you checked, what you found and what you did about it, not just "reviewed".
- **Exceptions are documented**: what happened, why, how it was fixed and when.
- **Approval comes before the action.** Approval after access was given or a change was made counts as a failure, unless it is the documented emergency path with its review afterward.
- **Vendor reliance is backed by the vendor's SOC report**, reviewed each year. See [Reading a vendor's SOC report](/guides/reading-a-vendors-soc-report/).
- **The person doing the check is independent** of what is checked.
- **Control work is done with named accounts**, so every action traces to a person.

## When things change

- **Changes to how a control works are recorded**, with what changed and when, because both versions may be tested.
- **Tool migrations plan for the evidence trail**, so earlier evidence isn't lost.
- **The written control matches what you do.** Update it when the way you work changes.
- **Configuration of automated controls is evidenced**, and changes to it go through change management.

## Walkthroughs and requests

- Describe what you do. If it differs from the procedure, say so, and update the procedure afterward with the date of the change.
- If you don't know, say "I'll confirm and come back to you."
- Answer the question asked.
- Raise problems early.

If you're unsure, Tech Risk can help.
